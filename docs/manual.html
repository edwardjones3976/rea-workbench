Start the demo

If Desk Code and Workbench are already configured on your PC, ask your Desk Code-enabled assistant to launch the REA Workbench demo through Desk Code. Give it the Workbench folder if you have more than one checkout. The launcher command runs through Desk Code’s permitted shell connector with the Workbench checkout as the working directory. Workbench opens as a separate Windows app.

python -B scripts\pilot.py demo --desk "C:\path\to\isolated-desk-code"

Select Create sample project. It imports the sample behavior notes and a Windows executable for REA inspection, selects the local deterministic model fixture, and fills the recipe input. You can repeat the demo using a fresh project. The fixture uses fixed answers and needs no provider key.

Review evidence before approving

  1. For your own work, create a project and use Import evidence for files in the supervisor’s approved import folder. The current pilot accepts UTF-8 notes, PE files, ZIP archives, and supported ASAR archives.
  2. Choose a model and select Draft from evidence. Read the request preview, then send it if the inputs and destination are appropriate.
  3. In Review rules and evidence, select a rule. Check its status, cited IDs, file name, digest, and saved text or REA inspection. The digest identifies the imported bytes. A rule with no references has an explicit empty state.
  4. Compare the rule to its evidence. Use Observed for behavior shown by the evidence, Inferred for interpretations, and Unknown when the evidence leaves a question open. Check the specification’s examples and expected outcomes too.
  5. Edit the specification if needed, select Save edits, then review the saved revision and select Approve specification.

The evidence panel opens saved excerpts locally and redacts recognized credential patterns. A reopened bundle can retain an evidence reference whose source excerpt was omitted from the export.

Build and test a tool

  1. Select Generate TypeScript once the specification is approved. Review the model request and confirm it. The generation request uses the approved behavior specification and tests.
  2. Read the generated source preview. Select Accept this version when it matches the behavior you reviewed.
  3. Select Run specification tests. Read the result and receipt before putting the tool into a recipe.

The accepted tool can be exported as an editable TypeScript library, CLI, and test source. Generated execution uses a pinned Docker image with network access disabled and no host bind mounts.

Compose and run a recipe

Use named inputs and outputs from earlier steps. The demo maps the imported artifact ID to a REA inspection, the log lines to the generated tool, and the diagnosis to a local MCP reference lookup.

[
  {"id":"inspect","kind":"rea","from":"input.artifact"},
  {"id":"diagnose","kind":"generated","from":"input.logs"},
  {"id":"reference","kind":"mcp","from":"diagnose"}
]
{"artifact":"E2","logs":["WARN first","ERROR last","INFO final","malformed"]}

Select Validate and save. Use Test through step with an ID such as diagnose, or Run recipe for the complete sequence. The sample diagnosis should contain one INFO, one WARN, one ERROR, and one malformed entry. The result panel also shows the Desk Code receipt.

Additional local plugins and MCP tools require trusted supervisor configuration. The launcher supplies a fixture plugin and MCP server. Adding the optional pinned rea-result component includes its original license and provenance in the export.

Export and reopen

Choose Export tool and recipe. Open the directory reported in the result and look for bundle.json, the spec, recipe, TypeScript library, CLI, and tests.

To reopen on another compatible installation, place bundle.json in its approved import folder. Use Import project bundle, review the available evidence, and reapprove the specification and source.

Before sharing, inspect the bundle and source for sensitive names, specification text, and evidence metadata. The bundle keeps evidence references and may retain REA inspection metadata. Original imported text and artifact bytes are omitted. For a recipe that needs a REA result, the bundle uses the inspection carried in its metadata where available.

Set up a source checkout

Install Windows prerequisites and use Desk Code for the setup commands. You need Docker Desktop, Python, compatible Node 26, REA Agents 6.10.1, and access to the Desk Code base commit recorded below.

  1. Prepare an isolated Desk Code checkout at 1bed52566498df491f7ff14c9a5789e7c07132e8. From that checkout, apply Workbench’s desk-code-pilot.patch with git apply using the patch’s full path. Leave the live Desk Code checkout in place.
  2. From the Workbench checkout, use the permitted Desk Code shell connector to run the commands below. Use the Node installer step if Electron’s runtime files are missing.
npm ci --no-audit --no-fund
node node_modules\electron\install.js
npm run build
docker pull node@sha256:0042e17d232a87a2cd485be1da7900fca4d10a4ad11b29e9285da1d2e54798c9
python -B scripts\pilot.py self-test --desk "C:\path\to\isolated-desk-code"

Use the demo command after the self-test. For your own projects, use launch in place of demo. The two modes have separate project and import stores in .pilot.

Troubleshooting

No Workbench window opens

Confirm that the command ran through Desk Code with the Workbench checkout as its working directory and the isolated checkout passed as --desk. Look at the launch receipt for a missing prerequisite or refused action.

The sample button is missing

Use demo and wait for Desk Code connected. launch starts the normal project store.

Evidence import was refused or a rule has no excerpt

Check the supervisor’s approved import folder and file type. A portable bundle can omit the original excerpt. Consult the original project or reimport an authorized copy, then update and save the rule’s references.

Tool generation or recipe execution fails

Confirm the spec was approved, the generated version was accepted, and the recipe was saved. Check the pinned Docker image and the Desk Code receipt. Before retrying a disconnected cloud request, check whether the earlier request completed.

Developer and assistant checks

python -B scripts\pilot.py smoke --desk "C:\path\to\isolated-desk-code"
python -B scripts\pilot.py sample-smoke --desk "C:\path\to\isolated-desk-code"

The self-test exercises REA inspection, local MCP and plugin calls, generated execution, evidence lookup, and bundle round-trip. The smoke checks start hidden Electron windows. sample-smoke exercises the guided sample and evidence review through the renderer.

Keep the Workbench checkout, the isolated Desk Code patch target, and test data separate. Report the command, backend, receipt, and whether UI interaction was automated or performed with the physical pointer.
